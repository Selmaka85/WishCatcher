## Product intent and truth boundary

WishCatcher is a discovery and contextual-interpretation system, not inherently a monetization tool.
ASTRA Genesis is a domain-neutral **logical structure composer** from intention and constraints,
not a business-plan chatbot. Its original specification calls for component catalogs,
rule-based combinations, scoring/selection and eventually verified generation across
software and non-software domains. Present code has only portions of that workflow.
A need observed in public discourse is not consent, a paying customer or validated demand.

## P1 — real, labeled evaluation: ENGINEERING SLICE DONE; EMPIRICAL OPEN

- Reuse scripts/evaluate_context.py for the existing **synthetic** RO/EN regression.
- New scripts/evaluate_context_ab.py requires operator-supplied labeled JSONL:
  unique id; language ro/en; boolean label; original actor-scoped conversation;
  annotation.reviewer_id, annotation.source_url and evidence_ids (nonempty for positives).
- Default minimum is 100 reviewed cases. This checks the metadata contract, NOT whether
  reviewers are genuinely independent; keep human audit separately.
- Rules arm uses existing ConversationContextResolver fallback + ContextQualityGate.
  Optional local arm uses the same inputs with an explicitly local-only
  OpenAI-compatible endpoint; remote hosts and unpaired model arguments are rejected.
- Report confusion counts, precision, recall, F1 by language, errors by hashed case ID,
  interpreted-vs-rule-fallback counts, elapsed time, flags. No raw transcript dumps.
- If the local model fails or yields ungrounded/abstaining output, the harness does NOT
  attribute the fallback prediction to the model. Partial model adoption = NO VERDICT.
- Existing CI uses provider-free tests only. No real labeled corpus or local-model
  comparison is claimed as already executed.

Example **schema only** (NOT a labeled real-world case):
    {"id":"SOURCE_ID","language":"en","label":true,
     "annotation":{"reviewer_id":"HUMAN_REVIEWER","source_url":"SOURCE_URL",
       "evidence_ids":["PRIMARY_ACTOR_MESSAGE_ID"]},
     "conversation":{"post_id":"PRIMARY_ACTOR_MESSAGE_ID",
       "post_author":"ACTOR","post_text":"SOURCE_TEXT","comments":[]}}

Usage on genuinely labeled operator-held data:
    python scripts/evaluate_context_ab.py --dataset /approved/cases.jsonl --minimum 100
    python scripts/evaluate_context_ab.py --dataset /approved/cases.jsonl \
      --minimum 100 --local-url http://127.0.0.1:11434/v1/chat/completions \
      --local-model qwen2.5:3b --output /tmp/context-ab.json

Human gold annotations must not be fabricated or tuned against the scored model.
Before comparing arms, keep sampling strata, baseline, model revision and gold labels frozen.

## P3 — refresh semantics: PURE HELPER DONE; DURABLE MIGRATION NOT AUTHORIZED

- conversation_revision_fingerprint(SourceConversation) computes a stable SHA-256
  revision of attributed message IDs, authors, parent relations, timestamps and text.
  A newly edited source should produce a new digest. No raw transcript is stored by it.
- Existing DiscoveryIndex still dedupes successful findings by source ID.
  Previously accepted threads DO NOT refresh after new replies; rejected threads
  lack durable negative-result cache. This remains a real semantic/cost defect.
- Proposed DB design for separate owner review:
  source_revisions(source, HMAC_source_key, content_hash, last_checked_at,
                   last_evaluated_at, result_status, model_revision, policy_revision)
  unique on (source, HMAC_source_key).
- Gate before migration: migration/rollback recipe, legacy DB read compatibility,
  cluster retraction/rebuild on corrected needs, quality-revision invalidation,
  expiry policy for rejected rows, redaction/retention, lock contention and
  crash-safe transactions. Do not infer that hash == verified source freshness.
- **No DB schema, scheduler, persistence behavior or cluster count changed.**

## P4 — original ASTRA Genesis principle: ISOLATED PROOF DONE; UNIVERSAL ENGINE OPEN

- Existing context_bridge.compose returns a hypothesis brief with generic
  input/processor/output/verification. BusinessPlanGenerator includes default
  financial assumptions and MVPStructureGenerator is software-template specific.
  Neither currently implements the full original universal rule composer.
- Added GenesisContextBridge.rank_declared_catalog: deterministic, bounded,
  provider-free operator-declared component catalog -> dependency-consistent subsets
  -> capability coverage -> lexicographic ranking on explicit comparable proxy
  cost/effort/maintenance units -> top 1–3 options.
- Max 10 catalog entries (<=1023 subsets). Reject unknown/self-dependencies,
  missing/invalid metrics, duplicate IDs and dependency cycles.
- Output is **UNVERIFIED_OPERATOR_DECLARED_STRUCTURE**; proxy units are NOT money,
  no external feasibility evidence or runnable code. Infeasible means NO_FEASIBLE_STRUCTURE.
- Existing compose, legacy MVP/business plan generators, API and default discovery
  remain untouched. The method is deliberately NOT auto-fed with LLM-invented catalogs.
- Next: versioned domain-specific component registry with verifiable references,
  constraint satisfaction, compatibility rules, uncertainty handling,
  Pareto/weighted tradeoffs, compositional tests in 3+ domains, independent
  feasibility checks and bounded output renderer. Architectural/API expansion
  should be reviewed before integration, not silently bolted on.
